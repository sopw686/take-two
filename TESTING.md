# Testing

## Run

```bash
uv run pytest            # fast: parser, alignment, thresholds, define heuristic, suggestions, stretch features (~1 s)
uv run pytest -m slow    # the synthetic fixture through real local speech-to-text (~5 s on GPU, ~30 s on CPU)
uv run pytest -m browser # Chrome's fake microphone records into the running app, script mode and Improvise (~90 s)
uv run python -m eval.run   # evaluation against labelled recordings -> eval/RESULTS.md (see eval/README.md)
cd frontend; npm test       # the frontend's pure logic under Node's built-in test runner (Node 22+ for the file glob)
```

## Known weak spots

- **Hear it and the examiner were never heard.** Every check of the voices was made from the DOM, a wrapped `speechSynthesis.speak` and traced audio events. Audible quality, whether the contour approximation sounds like a rising or falling end, and the real-room behaviour of the silence detector (fans, a distant microphone) have not been judged. A browser voice's pace at rate 1 is assumed to be about 170 wpm, so its absolute pace differs by voice; the plan's numbers are the plan's, not the voice's.
- **Settings outside their bounds are refused, not corrected,** when they come from somewhere other than the dialogs (an old browser store, a hand edit): every take is then refused with "bad settings" until Settings → Reset. Found by the examiner's browser test.

- **Whisper timestamp drift.** Word boundaries can be off by 0.1–0.3 s, more on long takes; line boundaries inherit this. Pauses are measured by the voice-activity detector instead, which is why `/` reads 0.36 s on a 0.30 s gap (VAD padding), not 0.46 s (Whisper's gap).
- **Misrecognized words** that are close in spelling now match (M12), but a badly misheard name or a short word still reduces a line's coverage. Rate uses the script's word count across the aligned span, so a wrong word does not read as slower speech; a line under the coverage threshold is paraphrased (timed, not rate-checked) only when its neighbours were found and some of its own words were heard, otherwise not found.
- **Numbers and names.** Spoken years and hundreds now match digits; "fifteen twenty" is read as the year 1520, so "15 to 20" said that way does not fully match. Unusual proper nouns often do not align.
- **Paraphrase detection** has been tested on hand-built transcripts and one reworded line of the example take, not on real paraphrasing speakers; two reworded lines in a row stay "not found".
- **Fillers.** Whisper usually omits "um" and "uh"; with the conventions preset on, the transcriber is nudged with a prompt, but the count stays a lower bound.
- **Emphasis** is experimental: loudness depends on microphone distance and head movement; pitch estimation fails on breathy or very low voices.
- **Heuristic `[DEFINE]`** can be fooled by cue words used for something else ("that is" as a plain phrase) and misses definitions by example that use none of the cue phrases.
- **Suggestions** are only as good as the model; caps limit over-marking but cannot make a weak reason good. The reasons are shown precisely so the user can judge them.
- **Improvise bands are conventions, not truths.** Defaults (pace 130–170 wpm, ≤ 2 fillers per 100 words, ≥ 5 semitones of pitch range, …) are starting points; uptalk and trailing-off depend on Whisper's sentence punctuation and on clean word timestamps.
- **Improvise clarity** is Whisper's word confidence: it also drops for rare names and technical terms said perfectly well.
- **Section tolerance floor** of 3 s means very short sections are rarely reported over or under.
